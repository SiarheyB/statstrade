# План фичи «Рекомендации» — поиск дневных уровней и сетапов «Пробой» / «Ложный пробой» на Binance

Основано на `docs/trade/алгоритм.pdf` (торговый алгоритм Герчика) и `docs/trade/твх.pdf` (точки входа).
Ветка: `feature/trade-recommendations`.

## 0. Скоуп (сознательно сужен по итогам обсуждения)

Фича ищет на дневном таймфрейме (D1) по **всем USDT-M бессрочным фьючерсам
Binance** (не спот — торгуем и в лонг, и в шорт, спот для шорта не годится)
ценовые уровни, близкие к текущей цене, и для каждого такого уровня оценивает
**только два** сетапа из документа:

1. **Пробой уровня** — продолжение движения через уровень.
2. **Ложный пробой (простой, ЛП)** — цена пробивает уровень, но не получает
   продолжения и возвращается обратно.

Не в скоупе (сознательно): «Отбой от уровня», «ЛП2Б», «СЛП», «Импульс-ретест»,
«Контртренд» — это отдельные модели из документа, к ним вернёмся отдельным
заходом, если этот MVP окажется полезным. Также не в скоупе: уровень первого
часа и лимитный уровень (нужны интрадей-объёмы/стакан, которых нет для всех
пар Binance — только для тех, что уже собирает orderbook-коллектор).

Фича — это **не чёрный ящик и не сигнал «покупай/продавай»**. Для каждого
уровня показываем, какие конкретно условия из документа сработали
(«+»/«−» факторы), и итоговый уклон: вероятен пробой / вероятен ложный
пробой / неопределённо. Решение — за пользователем, картинка помогает
готовиться к торговому дню (см. «Основные правила» документа — «весь анализ
выполняется при подготовке к торгам»).

## 1. Источник данных

- **Список пар**: `GET /fapi/v1/exchangeInfo` (Binance USDT-M Futures) — фильтр
  `status=TRADING`, `quoteAsset=USDT`, `contractType=PERPETUAL` (без квартальных
  контрактов — они истекают). Ожидаем ~300+ пар.
- **Дневные свечи**: `GET /fapi/v1/klines?interval=1d`, глубина ~250-300 баров
  (нужно минимум ~130 для критерия «экстремум за последние 6 месяцев» плюс
  запас для ATR/паттернов).
- Храним в **существующей** таблице `ObCandle` (`symbol`, `exchange='binance-futures'`,
  `interval='1d'`, `t`, `o`, `h`, `l`, `c`, `v`) — схема уже общая, отдельная
  таблица под свечи не нужна. Апсерт идемпотентен (`ON CONFLICT DO UPDATE`),
  так что переиспользование безопасно даже если пара уже частично собирается
  orderbook-коллектором.
- **Кто собирает**: новая функция в `collector/index.mjs`
  (`scanAllUsdtPairsDaily()`), отдельный таймер (раз в сутки — свечи дневные,
  чаще не нужно). Работает независимо от `OB_SYMBOLS`/`CANDLE_INTERVALS` —
  это отдельный, гораздо более широкий скан, только `1d`.
- Защита от перегрузки Binance: тот же паттерн, что уже есть для свечей —
  последовательные запросы с паузой/уважением rate-limit, `candlesRunning`-стиль
  флаг, чтобы не запускать скан поверх ещё идущего.

## 2. Детекция уровней (`src/lib/recommendations/levels.ts`)

На массиве дневных свечей одной пары (ascending) считаем:

- **ATR** — хай минус лоу дневного бара, среднее по последним 3-5 «нормальным»
  барам (исключая паранормальные: ≥1.5×ATR или ≤0.5×ATR).
- **Точка излома тренда** — локальные fractal-экстремумы (pivot high/low,
  N баров слева/справа). Сила: экстремум за 6 мес., паранормальный бар.
- **Зеркальный** — уровень, к которому цена подходила и как сопротивление,
  и как поддержка в разные периоды.
- **Исторический** — старый уровень, ещё не переподтверждённый (пока не
  «зеркальный»).
- **От параБАРа** — точка остановки бара с диапазоном ≥2×ATR.
- **GAP** — разрыв close(t-1)/open(t) (на крипте редко, но логику держим для
  полноты и на будущее, если добавим традиционные рынки).
- **Граница отката** — точка разворота коррекции к основному тренду.
- **Граница накопления/range** — верх/низ многобарной узкой консолидации.
- **Проторговка** — после прокола уровня ищем ≥2 бара, не перебивающих его.

Уровни со схожей ценой (в пределах допуска, например 0.15×ATR) схлопываем в
один, считаем «силу» (число подтверждений/касаний).

**Фильтр «близко к цене»**: оставляем уровни в пределах, например, 1.5×ATR от
текущей цены (настраиваемо) — это и есть «картинка для торговли сегодня».

## 3. Разметка «Пробой» / «Ложный пробой» (`src/lib/recommendations/breakoutSignals.ts`)

Для каждого уровня рядом с ценой считаем только то, что формализуемо по OHLC
(без стакана):

**Факторы за пробой** (из раздела «Предпосылки к пробою» и слайда «Пробой» из
твх.pdf):
- подход на малых барах (сужающийся диапазон последних N баров),
- накопление/консолидация перед уровнем (узкий range последних баров),
- поджатие (последовательные подходы к уровню с уменьшающимся отскоком),
- закрытие дневного бара близко к уровню (< 0.5×ATR),
- отсутствие отката после быстрого/паранормального подхода,
- нет реакции на предыдущий ложный пробой этого уровня (если был).

**Факторы за отбой/ложный пробой** (из раздела «Предпосылки к отбою»):
- длинное безоткатное движение к уровню (много участников уже в прибыли),
- подход на больших барах,
- день открылся дальше 0.5×ATR от уровня,
- закрытие дневки далеко от уровня (>0.5×ATR),
- дальний ретест (>30 дней с прошлого подхода),
- проторгованная зона сразу за уровнем («зона заражённости»).

**Определение факта ложного пробоя** (постфактум, для статистики/подсветки
исторических случаев на картинке): бар закрылся за уровнем, но не обновил
хай/лоу закрытия предыдущего дня относительно уровня, и цена вернулась
обратно без импульса.

Итог на уровень: список сработавших факторов (с той и другой стороны) +
итоговый тег `breakout_lean` / `false_breakout_lean` / `neutral` (простое
большинство факторов, не скрытый скоринг — то же самое пользователь видит
в списке факторов).

## 4. Хранение результатов

Новая таблица `LevelSetup` (миграция Prisma) — не привязана к пользователю,
общерыночные данные:
```
id            String   @id @default(cuid())
symbol        String
exchange      String   // "binance-futures"
levelPrice    Float
levelType     String   // break_point | mirror | historical | parabar | gap | pullback_border | range_border | reworked
strength      Int
distanceAtr   Float     // расстояние от текущей цены в долях ATR
bias          String    // breakout | false_breakout | neutral
signals       Json      // { for: string[], against: string[] }
atr           Float
currentPrice  Float
candlesFrom   DateTime  // диапазон свечей, использованных для картинки
candlesTo     DateTime
createdAt     DateTime  @default(now())

@@index([symbol, exchange])
@@index([bias])
```
Пересчитывается **целиком** раз в сутки (truncate + refill) — это «картина
дня», а не история по каждой паре.

## 5. Бэкенд API

- `POST /api/cron/recommendations` — пересчёт (защищено тем же секретом, что
  `/api/cron/sync`, см. `ENABLE_SCHEDULER`/внешний cron по `docs/SELF_HOSTING.md`).
- `GET /api/recommendations` — отдаёт список `LevelSetup`, отсортированный по
  `distanceAtr`, с опциональным фильтром по `bias`.
- `GET /api/recommendations/[symbol]/candles` — свечи для рендера SVG-снэпшота
  конкретной пары (или отдаём candlesFrom/candlesTo и рендерим из уже
  загруженных на фронте свечей одним общим запросом — решим на этапе UI).

## 6. Фронтенд

- Новый пункт в сайдбаре: **Сервис → Рекомендации**
  (`/dashboard/recommendations`), рядом с «Карта ликвидаций» / «Карта ордеров».
- Список карточек: пара, цена уровня, тип уровня, бейдж уклона (пробой /
  ложный пробой / нейтрально), список факторов, статичный SVG-снэпшот
  (дневные бары + горизонтальная линия уровня, без интерактива).
- Фича-флаг `tradeRecommendations` в `src/lib/features.ts` (по образцу
  `playbooks`/`monteCarlo`) — включаем только для себя на старте.

## 7. Порядок выполнения (по шагам, каждый — отдельный коммит)

1. Создать ветку `feature/trade-recommendations`.
2. `collector`: функция полного скана дневных свечей по всем USDT-M
   бессрочным фьючерсам Binance + таймер + защита от повторного запуска.
3. Prisma: миграция `LevelSetup`.
4. `src/lib/recommendations/levels.ts` — детекция уровней, юнит-тесты на
   синтетических свечах (по одному тесту на тип уровня).
5. `src/lib/recommendations/breakoutSignals.ts` — разметка факторов, юнит-тесты.
6. `/api/cron/recommendations` — пересчёт по всем парам, юнит-тесты.
7. `/api/recommendations` — выдача, юнит-тесты.
8. Фича-флаг `tradeRecommendations`.
9. UI: страница `/dashboard/recommendations` + пункт меню + SVG-снэпшот.
10. Прогон полного набора тестов + `npm run build`, проверка в браузере на
    тестовом аккаунте.
11. Ручная проверка на реальных парах (BTCUSDT и ещё 2-3) — картинка
    действительно показывает разумные уровни рядом с ценой.

## 8. Риски / открытые вопросы (отслеживать по ходу)

- Нагрузка на Binance API от скана 300-400 пар раз в сутки — оценить реальный
  вес запросов, при необходимости растянуть скан во времени.
- Точность классификации факторов — метод дискреционный по своей природе,
  ожидаем, что часть уровней будет спорной; это нормально и заявлено в
  документе явно («основано на визуальном анализе трейдера»).
- Список USDT-пар может включать низколиквидные шиткоины — возможно, стоит
  добавить фильтр по объёму на шаге 6/7, если картина будет зашумлена
  (решить по факту первого прогона).
